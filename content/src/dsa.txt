@skill dsa.complexity | Big-O and complexity analysis | - | 1 | 3
notes: Big-O describes how the running time or memory of an algorithm grows as the input size n grows, ignoring constant factors and lower-order terms. We usually reason about the worst case unless told otherwise. Count how many times the dominant operation runs: a single loop over n items is O(n), two nested loops over n are O(n^2), and a loop that halves the problem each step is O(log n). Sequential blocks add, nested blocks multiply, and we keep only the largest term, so n^2 + n becomes O(n^2). Space complexity counts extra memory beyond the input, including the recursion stack. Be able to rank common classes: 1, log n, n, n log n, n^2, 2^n, n!. In interviews, always state both time and space and justify them aloud.

@skill dsa.arrays | Arrays and indexing | dsa.complexity | 1 | 3
notes: An array stores elements in contiguous memory, which gives O(1) random access by index and excellent cache behaviour. Inserting or deleting in the middle costs O(n) because later elements must shift; appending to a dynamic array is amortised O(1) because capacity doubles occasionally. Indices run from 0 to n-1, and off-by-one mistakes at the boundaries are the most common bug, so check the first and last element and the empty array. Learn to traverse, reverse in place, rotate, find max and min, and remove duplicates from a sorted array. In-place algorithms use O(1) extra space by swapping or overwriting. Know the difference between array length and the last valid index. Many interview problems reduce to a clean single pass over an array, so practise tracking a running value like a maximum or a count.

@skill dsa.recursion | Recursion | dsa.complexity | 2 | 4
notes: Recursion solves a problem by calling the same function on smaller inputs until a base case stops it. Every recursive function needs a base case that returns directly and a recursive step that moves strictly toward it; missing either causes infinite recursion and a stack overflow. Each call uses a stack frame, so depth d costs O(d) space. Trace small inputs by hand to see the call tree. Time complexity follows a recurrence: factorial is T(n)=T(n-1)+O(1)=O(n), while naive Fibonacci is T(n)=T(n-1)+T(n-2), which is exponential because subproblems repeat. Recursion pairs naturally with trees, divide and conquer and backtracking. Any recursion can be rewritten with an explicit stack. Learn to define what the function returns, trust it on smaller inputs, and combine results.

@skill dsa.sorting_basic | Elementary sorting | dsa.arrays,dsa.complexity | 2 | 3
notes: Bubble sort repeatedly swaps adjacent out-of-order pairs, selection sort picks the minimum of the unsorted part and places it at the front, and insertion sort grows a sorted prefix by inserting each next element into place. All three run in O(n^2) worst case with O(1) extra space. Insertion sort is O(n) on nearly sorted input and is used inside real library sorts for small arrays. @skill dsa.binary_search | Binary search | dsa.arrays,dsa.complexity | 2 | 4
notes: Binary search finds a target in a sorted array by comparing with the middle element and discarding half the range, giving O(log n) time and O(1) space iteratively. The array must be sorted, otherwise the logic is invalid. Keep invariants clear: with low and high inclusive, loop while low <= high, compute mid = low + (high - low) / 2 to avoid integer overflow, and set low = mid + 1 or high = mid - 1. Off-by-one errors and infinite loops come from updating with mid instead of mid plus or minus one. The same idea works on any monotonic predicate, for example finding the smallest value that satisfies a condition, which powers lower bound, upper bound and search on the answer. Know how to return the insertion index when the target is absent.

@skill dsa.hashing | Hash tables and maps | dsa.arrays | 2 | 4
notes: A hash table maps keys to values by passing the key through a hash function that picks a bucket, giving average O(1) insert, lookup and delete. Collisions happen when different keys land in the same bucket and are handled by chaining, with a list per bucket, or by open addressing, probing for another slot. With a poor hash function or adversarial keys, operations degrade to O(n) in the worst case. The load factor, entries divided by buckets, triggers resizing, which rehashes everything and is amortised O(1) per insert. Keys must be hashable and immutable, and iteration order is not sorted in a plain hash map. Typical uses are counting frequencies, detecting duplicates, two-sum style lookups and grouping by a computed key. A hash set stores only keys and answers membership queries quickly.

@skill dsa.two_pointers | Two pointers | dsa.arrays,dsa.sorting_basic | 2 | 3
notes: The two-pointer technique uses two indices that move through a sequence to avoid a nested loop, often turning O(n^2) into O(n). In the opposite-ends pattern one pointer starts at the left and one at the right, and you move one inward based on a comparison; this solves pair-sum on a sorted array, container with most water and palindrome checks. In the same-direction pattern a slow pointer marks the write position while a fast pointer scans, used to remove duplicates or move zeros in place. The key is a clear rule for which pointer moves and a proof that no valid answer is skipped. Sorting first can enable the technique at a cost of O(n log n). Always handle empty and single-element inputs, and be careful that pointers do not cross when they should not.

@skill dsa.sliding_window | Sliding window | dsa.two_pointers | 3 | 4
notes: A sliding window maintains a contiguous subarray or substring defined by left and right boundaries, expanding the right edge and shrinking the left edge while tracking a running sum, count or set. For a fixed-size window of length k you add the new element and remove the one that leaves, giving O(n) rather than O(nk). For a variable-size window you expand until a condition breaks, then shrink until it holds again, which handles longest substring without repeating characters and smallest subarray with sum at least a target. Each pointer only moves forward, so total work is O(n) even though there is a loop inside a loop. Use a hash map or array of counts to track window contents. Decide clearly whether the window is valid after each expansion, and update the best answer at the right moment.

@skill dsa.prefix_sums | Prefix sums | dsa.arrays | 2 | 3
notes: A prefix sum array stores in prefix[i] the sum of the first i elements, so the sum of any range from l to r (inclusive) is prefix[r+1] - prefix[l] in O(1) after O(n) preprocessing. This turns repeated range-sum queries from O(n) each into O(1) each. Use an extra leading zero so empty ranges and ranges starting at index 0 need no special case. The idea extends to 2D grids with a rectangle formula, to counting subarrays with a given sum using a hash map of earlier prefix values, and to difference arrays that apply many range updates and recover the final array with one prefix pass. Beware of integer overflow with large sums and off-by-one errors in the indices. Prefix sums only work well when the array is static or updates are rare.

notes: A singly linked list stores each element in a node with a value and a pointer to the next node; there is no random access, so reaching the kth node costs O(k). @skill dsa.stack | Stacks | dsa.arrays,dsa.linked_list | 2 | 3
notes: A stack is a last-in first-out structure with push, pop and peek, all O(1) when built on an array or linked list. Popping from an empty stack is an error you must guard against. Stacks model nested or reversed behaviour: the function call stack, undo history, backtracking and expression evaluation. Any recursion can be rewritten iteratively with an explicit stack, which avoids stack overflow on deep inputs. When a problem mentions the most recent item, matching pairs or reversing order, think stack first. Always check emptiness before peeking, and remember the stack must be empty at the end for balanced input.

@skill dsa.queue | Queues and deques | dsa.stack,dsa.linked_list | 2 | 3
notes: A queue is first-in first-out: enqueue adds at the back and dequeue removes from the front, both O(1) with a linked list or a circular array. A circular buffer reuses space by wrapping indices with a modulus, and you must distinguish full from empty, typically by tracking size or leaving one slot unused. Know how to implement a stack with two queues and a queue with two stacks.

@skill dsa.monotonic_stack | Monotonic stack | dsa.stack,dsa.arrays | 3 | 4
notes: A monotonic stack keeps its elements in sorted order, increasing or decreasing from bottom to top, by popping elements that would break the order before pushing a new one. It answers next greater element, previous smaller element, daily temperatures, largest rectangle in a histogram and stock span questions in O(n) total, because each element is pushed once and popped at most once. Store indices rather than values when you need distances or positions. When a new element arrives, every popped element has just found its answer: the new element is its next greater or smaller value. After the loop, elements left on the stack have no answer, often meaning a default such as minus one. Decide the direction of monotonicity from the question, for example a decreasing stack for next greater element.

notes: Backtracking builds candidates step by step and abandons a path as soon as it cannot lead to a valid solution, undoing the last choice to try another. notes: Dijkstra's algorithm finds shortest paths from one source to all vertices in a graph with non-negative edge weights. Keep a distance array initialised to infinity except zero for the source, and a min-heap of vertex and distance pairs. Repeatedly pop the closest unfinalised vertex and relax its outgoing edges: if dist[u] + w is smaller than dist[v], update dist[v] and push it. On unweighted graphs plain BFS is enough and faster. Floyd-Warshall solves all pairs in O(V^3).

@skill dsa.mst | Minimum spanning trees | dsa.union_find,dsa.shortest | 4 | 4
notes: A spanning tree of a connected undirected graph with V vertices uses exactly V minus one edges, connects every vertex and has no cycle; a minimum spanning tree has the smallest possible total weight. Kruskal's algorithm sorts all edges by weight and adds each edge if it connects two different components, checked with Union-Find, in O(E log E). Prim's algorithm grows a tree from one vertex, repeatedly adding the cheapest edge leaving the tree using a min-heap, in O((V + E) log V). Both rely on the cut property: the lightest edge crossing any cut belongs to some MST. If edge weights are distinct the MST is unique. An MST minimises total weight, not the path between two given vertices, so it is not the same as a shortest-path tree. A disconnected graph has a minimum spanning forest instead.

notes: Dynamic programming solves problems whose solution can be built from solutions to overlapping subproblems with optimal substructure. Naive recursion repeats the same subproblems exponentially often; memoization caches each result the first time, and tabulation fills a table bottom up in dependency order. Dynamic programming differs from divide and conquer because subproblems overlap, and from greedy because it considers all choices of the recurrence rather than committing to one. notes: A greedy algorithm builds a solution by repeatedly taking the locally best choice and never reconsidering it. @skill dsa.intervals | Interval problems | dsa.sorting_adv,dsa.greedy,dsa.heap | 3 | 4
notes: Interval problems represent ranges as start and end pairs and usually start by sorting by start time. To merge overlapping intervals, sort, then keep a current interval and extend its end to the maximum when the next start is at most the current end; otherwise emit it and start a new one. Two intervals overlap when each starts before the other ends, and you must decide whether touching endpoints count as overlap. To insert a new interval into a sorted list, copy intervals ending before it, merge those overlapping it, then copy the rest. Minimum meeting rooms is the maximum number of simultaneous intervals, found with sorted start and end arrays or a min-heap of end times. Removing the fewest intervals to eliminate overlap is the greedy activity selection by earliest end. Sorting dominates, so these run in O(n log n).
